# Workflow Яндекс Диска

## Область

Один пользователь и один аккаунт Яндекс Диска. Токен задаётся вне репозитория. Многопользовательская OAuth-система и UI авторизации в V1 не нужны.

Перед реализацией сверить актуальные URL, scopes, заголовки, коды ошибок и ограничения в официальной документации: https://yandex.ru/dev/disk-api/doc/ru/

## Конфигурация

```text
YANDEX_DISK_TOKEN=<secret>
YANDEX_DISK_ROOT=/AI Exports
```

Токен передаётся в соответствии с актуальной документацией Яндекс OAuth. Не хранить его в plan, job DB, логах или MCP response.

## Подготовка назначения

1. Нормализовать remote path в POSIX-виде независимо от ОС MCP.
2. Проверить, что путь остаётся внутри `YANDEX_DISK_ROOT`.
3. Создать недостающие директории идемпотентно.
4. До загрузки получить metadata существующих целей и применить collision policy.

## Загрузка

Рекомендуемый надёжный путь:

1. Запросить у REST API URL для загрузки конкретного remote path.
2. Передать байты из временного файла или bounded stream.
3. Ограничить параллельность конфигурацией.
4. Считать сетевые timeout/429/5xx потенциально retryable, но соблюдать официальный retry guidance.
5. После неоднозначного timeout сначала проверить remote metadata, а не загружать дубликат вслепую.

Если API поддерживает загрузку по внешнему URL, её можно добавить как оптимизацию только после проверки поведения signed Figma URLs, статуса асинхронной операции и итоговой верификации. Надёжный локальный/streaming fallback обязателен.

## Верификация

Файл получает статус `verified`, только если:

- remote resource существует по ожидаемому пути;
- тип соответствует файлу;
- размер совпадает;
- checksum совпадает, если обе стороны предоставляют сопоставимую checksum;
- имя и каталог совпадают с manifest.

Если удалённая checksum недоступна, размер обязателен, а локальную SHA-256 сохранить в job report до cleanup.

Для архива дополнительно открыть локальный ZIP до загрузки и проверить entries; после загрузки сверить размер/checksum.

## Очистка

- Локальный item удаляется только после `verified`.
- Локальная директория job удаляется после `all expected items verified` и записи итогового отчёта в persistent state.
- При `partial` или `failed` временные файлы сохраняются для resume.
- `cleanup_job` для незавершённого job требует явного подтверждения и сообщает о риске потери возможности resume.
- Старые orphan temp dirs очищаются retention worker только после сопоставления с job DB и безопасного срока хранения.

## Конфликты

- `error` — остановить до экспорта/загрузки.
- `version` — добавить стабильный суффикс версии ко всему job, а не случайно к отдельным файлам.
- `skip_identical` — пропустить только после проверки идентичности.
- `overwrite` не включать в V1 по умолчанию; если будет добавлен, требовать отдельного явного подтверждения пользователя.

## Результат MCP

Возвращать приватные пути и статистику. Публичную ссылку создавать только при явном `publish: true`, желательно отдельным подтверждаемым действием. Никогда не публиковать корневую пользовательскую папку.
