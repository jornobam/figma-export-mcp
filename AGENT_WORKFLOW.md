# Обязательный workflow AI-агента

## Цель

Пользователь не должен изучать Figma node IDs или писать YAML. Он описывает результат обычным языком. Агент переводит намерение в точный план через MCP.

## Стадии

### 1. Понять исходный запрос

Собрать известные параметры:

- Figma URL;
- какие сущности нужны;
- ограничивающие значения: цвета, коды, товары, фасовки;
- формат и масштаб;
- количество или правило количества;
- порядок;
- схема имён;
- структура папок/архивов;
- корневая папка Яндекс Диска;
- политика при совпадении имён.

Не спрашивать повторно то, что пользователь уже определил.

### 2. Исследовать файл

Вызвать `check_connections`, затем `inspect_figma_file`. Использовать `analyze_figma_layout` и `query_nodes`, чтобы подтвердить, как запрос соотносится с реальной структурой.

Не переносить предположения из предыдущего Figma-файла.

### 3. Уточнить неоднозначности

Агент обязан задать вопрос до создания подтверждаемого плана, если ответ может изменить:

- состав файлов;
- порядок;
- экспортируемый уровень узла;
- имена;
- структуру папок;
- overwrite/version behavior;
- публичность результата;
- формат/scale.

Вопросы должны быть короткими и предметными. Если возможно, приводить обнаруженные варианты и counts.

Пример:

> Нашёл 7 строк по 8 карточек. Под «обложкой» вы имеете в виду первую карточку каждой строки или фрейм с текстом «Основная информация»?

### 4. Сформировать draft

Вызвать `create_export_plan`. Если MCP вернул `clarifications`, задать их пользователю, обновить параметры и создать новый draft.

### 5. Показать preview

До подтверждения сообщить минимум:

```text
Источник: <file/page>
Выбрано: N узлов
Экспорт: PNG 1x
Порядок: строки сверху вниз, внутри слева направо
Папки: <template>
Имена: <template + 3 examples>
Яндекс Диск: <destination>
Конфликты: нет / описание
Предупреждения: нет / описание
```

После этого запросить явное подтверждение.

### 6. Подтвердить и выполнить

Только после явного согласия пользователя вызвать `confirm_export_plan` с текущим digest, затем `execute_export_plan`.

Нельзя считать подтверждением:

- исходное сообщение с общим желанием скачать файлы;
- молчание пользователя;
- согласие на другой digest;
- подтверждение, данное до показа итогового count/naming/destination.

### 7. Дождаться и проверить

Отслеживать `get_export_status` с разумным интервалом. При retryable ошибках использовать встроенное ожидание/job state. Не создавать дубликат job.

При partial result сообщить, что готово, что не готово и можно ли безопасно продолжить.

### 8. Завершить

После `completed + verified` сообщить:

- число успешно загруженных файлов;
- число архивов и папок;
- путь Яндекс Диска;
- были ли переименования/коллизии;
- были ли пропуски;
- удалены ли локальные временные данные.

Публичную ссылку создавать только если пользователь её запросил.
