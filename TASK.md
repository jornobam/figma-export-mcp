# Задание автономному Codex: разработать Figma Export MCP

Создай в этом репозитории production-ready MCP-сервер согласно всем приложенным спецификациям.

## Результат

Пользователь общается со своим AI-агентом естественным языком. Агент подключает MCP, исследует указанный Figma-файл, уточняет недостающие правила, создаёт и показывает план экспорта. Только после явного подтверждения MCP массово экспортирует выбранные узлы, упорядочивает и переименовывает файлы, создаёт требуемую структуру папок или архивы, загружает результат в один аккаунт Яндекс Диска, проверяет удалённые объекты и удаляет локальный мусор.

Продукт должен поддерживать разные структуры Figma: элементы могут лежать в строках, колонках, вложенных фреймах, секциях, компонентах или группах; пользователю могут требоваться все карточки, только обложки, отдельные позиции из каждой строки или комбинация семантических и геометрических условий.

## Обязательные результаты разработки

1. TypeScript-проект с техническим STDIO entrypoint MCP.
2. Полная реализация инструментов из `MCP_TOOLS.md` или совместимый, обоснованно улучшенный контракт.
3. Встроенное server-level поле `instructions` с протоколом из `AGENT_WORKFLOW.md`.
4. Клиент Figma REST API с кешированием, пакетным рендером, retry/backoff и учётом `Retry-After`.
5. Универсальный движок выборки и export plan.
6. Клиент Яндекс Диска: создание каталогов, загрузка, проверка, повторение ошибок и безопасная очистка.
7. Надёжное хранилище состояния jobs, пригодное для возобновления после перезапуска процесса.
8. Unit, integration, contract и end-to-end тесты без обязательных реальных токенов.
9. Документация установки и подключения к MCP-клиентам на Linux, macOS и Windows.
10. Примеры настройки через переменные окружения, без секретов.
11. Пакетирование, позволяющее установить один и тот же релиз на трёх ОС.
12. Отчёт о соответствии `ACCEPTANCE_CRITERIA.md`.

## Порядок работы

1. Изучи спецификацию и официальные API.
2. Создай краткий implementation plan и `docs/DECISIONS.md`.
3. Спроектируй доменные типы и JSON Schema до сетевых клиентов.
4. Реализуй вертикальный сценарий: inspect → plan → preview → confirm → export → upload → verify → cleanup.
5. Добавь расширенные селекторы, геометрию и восстановление jobs.
6. Добавь тесты ошибок, лимитов, конфликтов имён и частичных загрузок.
7. Подготовь документацию и примеры конфигурации MCP.
8. Выполни полный аудит критериев приёмки и устрани пробелы.

## Самостоятельность

Принимай обратимые технические решения самостоятельно. Не останавливайся ради выбора библиотек или внутренней структуры каталогов. Задавай вопрос владельцу только если отсутствующая информация меняет продуктовый контракт, требует секретов или делает безопасную проверку невозможной.

Не запрашивай и не вставляй реальные токены в исходники. Для live smoke test оставь отдельную документированную команду, которую владелец сможет запустить самостоятельно.

В финальном сообщении перечисли реализованные возможности, результаты тестов, оставшиеся ограничения официальных API и точные команды установки/подключения MCP.
