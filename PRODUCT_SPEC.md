# Продуктовая спецификация

## Проблема

В больших Figma-файлах изображения и карточки организованы непоследовательно. В одном файле нужные элементы идут блоками по восемь, в другом — вложенными фреймами, в третьем нужны только обложки или несколько позиций из каждой строки. Ручной экспорт, сортировка, переименование и загрузка сотен файлов занимают много времени и приводят к ошибкам.

## Пользователь

Один владелец использует один аккаунт Figma и один аккаунт Яндекс Диска. Он обращается к AI-агенту через MCP-совместимый клиент. MCP может работать на Linux, macOS или Windows.

## Основной сценарий

Пользователь пишет, например:

> Скачай только обложки краски для цветов RAL 6021, 6027 и 7047. Разложи по цвету, внутри по фасовке. Перед скачиванием уточни порядок и схему имён.

Ожидаемое поведение:

1. Агент получает Figma URL и вызывает инспекцию.
2. MCP возвращает компактную структуру файла и возможные закономерности.
3. Агент уточняет только действительно отсутствующие решения.
4. MCP создаёт immutable draft plan и preview manifest.
5. Агент сообщает количество, выборку, порядок, имена и путь назначения.
6. Пользователь явно подтверждает план.
7. Агент подтверждает digest плана через MCP и запускает job.
8. MCP экспортирует, загружает и проверяет файлы.
9. MCP удаляет локальные временные файлы только после полной проверки.
10. Агент возвращает итоговую статистику и пути/ссылки Яндекс Диска.

## Функциональные требования

### Источник Figma

- Принимать URL файла, URL конкретного узла, `file_key` и необязательный `node_id`.
- Получать дерево, имена, тексты, типы, компоненты, видимость и геометрию.
- Кешировать снимок по `file_key + version`.
- Уметь ограничивать чтение выбранными страницами или узлами.
- Пакетно экспортировать несколько node ID.
- Поддерживать PNG, JPG, SVG и PDF, минимум PNG 1x в MVP.

### Отбор

- Точные и regex-сопоставления имён и текстов.
- Фильтры по типу, видимости, размеру и иерархическому пути.
- Поиск по текстам потомков и свойствам компонента.
- Группировка по строкам и колонкам на основании геометрии.
- Выбор первой/последней/N-й позиции, диапазона, списка позиций или каждого N-го элемента.
- Сочетание условий `all`, `any`, `not`.
- Выбор экспортируемого узла относительно совпадения: сам узел, предок подходящего типа, ближайший frame/group/component или явный ancestor selector.
- Ручные include/exclude node ID.
- Явное управление порядком.

### План и согласование

- План имеет версию схемы, ID, digest и состояния `draft`, `confirmed`, `running`, `completed`, `partial`, `failed`.
- Preview не запускает рендер всех изображений.
- Preview показывает representative samples, итоговое количество, предупреждения и таблицу будущих путей.
- Неоднозначности возвращаются как `clarifications[]`.
- Выполнение возможно только после подтверждения текущего digest.

### Имена и папки

- Шаблоны с переменными из текста, иерархии, строк/колонок, capture groups и последовательных индексов.
- Сохранение Unicode и кириллицы.
- Кроссплатформенная очистка запрещённых символов.
- Детектирование конфликтов до экспорта.
- Политики конфликтов: `error`, `version`, `skip_identical`; перезапись по умолчанию запрещена.
- Опциональные ZIP-архивы по всему job или по группам.

### Яндекс Диск

- Один OAuth-токен/аккаунт.
- Конфигурируемый корневой каталог.
- Создание вложенных папок.
- Загрузка с ограниченной параллельностью.
- Проверка удалённого размера и доступной контрольной суммы.
- Идемпотентное повторение частично завершённого job.
- Публичные ссылки создаются только по явному запросу.
- Удаление локальных временных файлов после полной проверки.

## Нефункциональные требования

- Поддержка Linux, macOS, Windows.
- Работа с тысячами узлов без переполнения контекста модели.
- Структурированные результаты инструментов.
- Диагностируемые ошибки без утечки секретов.
- Возобновление после завершения MCP-процесса.
- Предсказуемая работа при Figma 429/5xx и сетевых сбоях.
- Никаких изменений исходного Figma-файла.

## Не входит в первую версию

- Многопользовательский SaaS.
- Веб-интерфейс.
- Редактирование Figma.
- Хранение нескольких профилей Яндекс Диска.
- Распознавание содержимого картинок через отдельную vision-модель как обязательная зависимость.
- Пользовательский CLI.
